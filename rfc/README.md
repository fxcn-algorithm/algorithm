# RFC:权重与规则的变更流程

fxcn.com 在 [/algorithm](https://fxcn.com/algorithm) 上承诺:

> 任何权重调整都在 GitHub 上以 RFC 形式公示 30 天后才会生效。

这个目录就是兑现那句话的地方。

## 为什么要有这道流程

评分会影响读者对一家经纪商的判断。如果运营方可以随时悄悄改权重,
「算法开源」就退化成了「公开一份随时可能变的数字」。**公示期的作用是让改动可被质疑。**

## 流程

1. **提 PR**,在 `rfc/` 下新增 `NNNN-简短标题.md`,用下面的模板。
2. PR 标题以 `RFC:` 开头,并附上**改动前后 129 家的分数 diff**
   (`python3 algorithm/score.py` 跑新旧 `rules.json` 各一次即可)。
3. **公示 30 天**,期间任何人可以在 PR 下提出异议。
4. 30 天期满且异议已被回应 → 合并 → 同步到生产实现 → 在 fxcn.com 的
   更新日志与受影响经纪商的时间线上留痕。

**例外**:修正明显的实现 bug(算出来与规则文档不符)不需要 30 天公示,
但必须单独开 PR、写清是「实现对齐文档」而非「改规则」,并附分数 diff。

## 模板

```markdown
# RFC-NNNN:标题

- 状态:草案 / 公示中(起止日期)/ 已采纳 / 已否决
- 提出者:
- 影响的算法版本:v1 → v?

## 问题
现在的规则在什么情况下给出了不合理的结果?**给具体例子,不要只讲道理。**

## 提案
`rules.json` 的哪几行改成什么。

## 影响
- 129 家中有 N 家分数变化,最大变动 ±X.X
- 颜色档位变化:green N→N, yellow N→N, orange N→N, red N→N
- 逐家 diff:(贴表格或附文件)

## 反对意见与回应
公示期内收到的异议,逐条回应。
```
